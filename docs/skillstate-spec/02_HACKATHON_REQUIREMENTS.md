# Hackathon PS1 Coverage Matrix

The implementation must visibly cover every requirement from EduPath.

| Problem statement requirement | SkillState implementation |
|---|---|
| Current skills | Claimed State + Verified State |
| Experience | Profile + Evidence Ledger |
| Target role | Destination |
| Career goal | Destination + target timeline |
| Resume analysis | Evidence ingestion |
| Portfolio analysis | Evidence ingestion |
| Certificate analysis | Evidence ingestion |
| Project descriptions | Evidence ingestion |
| Skill-gap identification | Expected State vs Verified State |
| Structured learning objectives | Gap nodes + prerequisite ordering |
| Learning-resource recommendations | Resource Matcher |
| Weekly learning plan | Adaptive Journey weekly view |
| Practice tasks | Verify / Repair tasks |
| Project ideas | Proof Builder |
| Track completed activities | Activity Ledger |
| Update plan dynamically | Replan event |
| Identify repeated struggles | Struggle Detector |
| Skills acquired | Progress Report |
| Skills in progress | Progress Report |
| Remaining gaps | Progress Report |
| Recommended next steps | Next Best Actions |
| Natural-language questions | Ask SkillState |
| Personalized rather than generic | Stage + evidence + time + certainty aware |

## Demo requirement

The 3-minute demo must visibly show at least:

1. destination selection,
2. resume/project evidence upload or sample evidence import,
3. claimed vs verified distinction,
4. one proof task,
5. a detected gap,
6. an automatically changed plan,
7. a recommended project/resource,
8. a progress report,
9. natural-language question,
10. one alternative-career comparison to prove the engine is not engineering-only.

## Explicit judging defense

Never present SkillState as a course recommendation engine.

Pitch it as:

**A continuously updated model of where the learner actually is relative to where they want to go.**
